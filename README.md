# نقشات — متجر استكيرات نقشات الحناء

متجر إلكتروني عربي (RTL) فاخر أنثوي لاستكيرات نقشات الحناء النسائية.

**Brand:** نقشات (Naqshat)

## التقنيات

- Next.js 14 (App Router) + TypeScript
- Tailwind CSS
- Zustand (سلة + مفضلة + شاهدتِ مؤخرًا + طلبات + واجهة الدرج) مع `localStorage`
- بيانات وهمية فقط — بدون Backend / Database / Auth

## التشغيل محليًا

```bash
cd ecommerace-design
npm install
npm run dev
```

ثم افتحي: [http://localhost:3000](http://localhost:3000)

### أوامر أخرى

```bash
npm run build   # بناء الإنتاج
npm run start   # تشغيل البناء
npm run lint    # فحص ESLint
```

## المرحلة 3 — إتمام الطلب

تدفق وهمي كامل بدون Backend:

1. من السلة → **المتابعة لإتمام الشراء**
2. بيانات العميلة (اسم + جوال)
3. عنوان محفوظ أو عنوان جديد (محافظة، مدينة، حي، شارع، تفاصيل، هاتف، موقع اختياري، تسمية المنزل/العمل)
4. طريقة التوصيل: **التوصيل العادي** أو **استلام من المتجر** (مع الرسوم)
5. الدفع: **تحويل بنكي فقط** + حسابات وهمية + تنبيه إرسال إيصال واتساب
6. مراجعة المنتجات والكميات والخصم ورسوم التوصيل والإجمالي (YER)
7. **تأكيد الطلب** → رقم مثل `ORD-2026-00125` + رسالة نجاح + زر واتساب
8. الطلب يُحفظ في `localStorage` (`naqshat-orders`) للمرحلة 4

### التحقق يدويًا

1. أضيفي منتجًا متوفرًا إلى السلة
2. افتحي `/checkout` (أو من السلة / درج السلة)
3. أكملي الخطوات حتى **تأكيد الطلب**
4. تأكدي من ظهور رقم الطلب وزر واتساب
5. افتحي DevTools → Application → Local Storage → `naqshat-orders`

سلة فارغة على `/checkout` تعيد التوجيه لمحتوى فارغ مع رابط للمنتجات/السلة.

## المرحلة 2 — السلة والمفضلة

- درج سلة منزلق (RTL) من أيقونة السلة في الشريط
- صفحة سلة كاملة مع كميات، حذف، خصومات، ومنتجات غير متوفرة
- مفضلة مع إضافة للسلة وإزالة
- سجل مشاهدة محفوظ في `localStorage`


## المرحلة 4 — حساب العميلة والطلبات

واجهة وهمية بالكامل (localStorage):

- **حسابي** `/account` — اختصارات للمعلومات والعناوين والطلبات والمفضلة والتقييمات
- **معلوماتي** — تعديل الاسم والجوال والبريد
- **عناويني** — قائمة / إضافة / تعديل عناوين محفوظة (`naqshat-customer`)
- **طلباتي** — قائمة بالرقم والتاريخ وعدد المنتجات والإجمالي وحالة الدفع وحالة الطلب
- **تفاصيل الطلب** — منتجات، كميات، أسعار، خصم، توصيل، إجمالي، عنوان، دفع، **خط زمني مرئي**
- طلبات تجريبية متنوعة الحالات تُدمج مع طلبات المستخدم من المرحلة 3
- حالات الطلب: بانتظار الدفع · جاري مراجعة الدفع · تم تأكيد الدفع · جاري التجهيز · جاهز للتوصيل · خرج للتوصيل · تم التسليم · تم الإلغاء
- شريط التنقل: أيقونة **حسابي** → `/account`

### التحقق يدويًا

1. افتحي `/account` من أيقونة المستخدم في الشريط
2. راجعي طلباتي — يجب ظهور طلبات تجريبية حتى بدون شراء
3. افتحي تفاصيل طلب وشاهدي الخط الزمني
4. عدّلي معلوماتي أو عنوانًا واحفظي — تُحدَّث في Local Storage
5. أتممي طلبًا من `/checkout` ثم افتحي تفاصيله من صفحة النجاح
6. `npm run build` يجب أن ينجح


## المرحلة 5 — التقييمات

واجهة تقييمات وهمية (localStorage `naqshat-reviews`):

- **صفحة المنتج** — ملخص التقييم، توزيع النجوم، قائمة المراجعات (اسم، نجوم، تاريخ، تعليق، صور اختيارية)
- **طلب مُسلَّم** — في تفاصيل الطلب بحالة **تم التسليم** يظهر زر **قيّمي النقشة** لكل منتج
- **نافذة التقييم** — اختيار نجوم، تعليق، صور اختيارية؛ عند الإرسال تظهر رسالة «تم إرسال تقييمك بنجاح»
- **تقييماتي** `/account/reviews` — قائمة تقييمات العميلة المُرسلة

### التحقق يدويًا

1. افتحي منتجًا مثل `/products` → نقشة لها مراجعات (مثل تاج العروس) وراجعي الملخص والتوزيع
2. من `/account/orders` افتحي طلبًا بحالة **تم التسليم** (مثل `ORD-2026-00118`)
3. اضغطي **قيّمي النقشة** على منتج، أرسلي التقييم، وتأكدي من التوست
4. افتحي `/account/reviews` لرؤية التقييم المحفوظ
5. DevTools → Application → Local Storage → `naqshat-reviews`
6. `npm run build` يجب أن ينجح



## المرحلة 6 — واجهة التسويق

صقل أسطح التسويق ببيانات وهمية (بدون Backend):

- **شريط الإعلانات** — تدرج داكن + شارة «عروض محدودة» ورسائل للعروس/المناسبات
- **البطل (Hero)** — شريحة تسويقية أنثوية مع شارة «نقشات · نساء · مناسبات»
- **صفحة العروض** `/offers` — حملات كاملة + بطاقات منتجات: صورة، اسم، سعر قديم، سعر جديد، نسبة خصم، تاريخ انتهاء، عدّاد تنازلي
- **الرئيسية** — أقسام: جديد، الأكثر طلبًا، عروض، مميز، نقشات المناسبات + شريط مناسبات (عروس/زفاف/خطوبة/عيد/حفلة)
- **شارات الخصم** موحّدة عبر بطاقات المنتجات والعروض وصفحة المنتج

### التحقق يدويًا

1. افتحي `/` وراجعي شريط الإعلانات، البطل، شريط المناسبات، وأقسام العروض/الأكثر طلبًا/الجديد/المميز
2. افتحي `/offers` — يجب ظهور حملات بعدّاد وبطاقات منتجات بالأسعار والخصم وتاريخ الانتهاء
3. تأكدي من توحيد شارة الخصم على البطاقات
4. `npm run build` يجب أن ينجح



## المرحلة 7 — البحث المتقدم والتوصيات

اكتشاف منتجات وهمي بالكامل (بدون Backend):

- **بحث سريع (Overlay)** — من شريط البحث في النافبار (أو ⌘K / Ctrl+K): اقتراحات أثناء الكتابة للمنتجات والأقسام وأنواع النقوش والمناسبات + عمليات بحث سابقة وشائعة
- **فلاتر** على `/products` ونتائج `/search`: القسم، نوع النقشة، المناسبة، السعر، التوفر، التقييم، الخصم — شريط جانبي على سطح المكتب ودرج على الجوال
- **ترتيب**: الأحدث، الأكثر مبيعًا، الأعلى تقييمًا، السعر تصاعدي/تنازلي (+ المميزة)
- **توصيات صفحة المنتج**: نقشات مشابهة، منتجات مرتبطة، «قد تحتاجين أيضًا»، شاهدتِ مؤخرًا — عبر مساعدات وهمية في `lib/recommendations.ts` و`lib/search.ts`

### التحقق يدويًا

1. اضغطي شريط البحث في النافبار → ابدئي بالكتابة (مثل «عروس» أو «ناعمة») وراجعي الاقتراحات
2. Enter أو «عرض كل النتائج» → `/search?q=` مع فلاتر وترتيب
3. في `/products` جرّبي فلتر المناسبة/النوع/الخصم والترتيب من الشريط أو الدرج
4. افتحي منتجًا وراجعي أقسام: نقشات مشابهة · مرتبطة · قد تحتاجين أيضًا · شاهدتِ مؤخرًا
5. `npm run build` يجب أن ينجح

## المرحلة 8 — صقل واجهة الإنتاج

تمريرة صقل كاملة لإحساس إطلاق جاهز (بدون Backend):

- **طباعة وتباعد وRTL** — فئات `.page-title` / `.page-subtitle`، أزرار بحد أدنى للمس، `overflow-x: clip`، دعم `safe-area` للشريط السفلي في صفحة المنتج
- **مكونات موحّدة** — `EmptyState` (بحث/سلة/مفضلة/طلبات/تقييمات…)، `StockBadge` / `StockOverlay` (متوفر · كمية منخفضة · نفدت)، `ConfirmDialog`، `ErrorState`، هياكل تحميل `PageSkeleton` / `ProductGridSkeleton`
- **حالات النظام** — `app/loading.tsx`، `app/error.tsx`، صفحة **404** أغنى بروابط سريعة، توستات ملوّنة حسب النجاح/معلومة/خطأ
- **حواريات تأكيد** — تفريغ السلة، حذف عنوان، مسح سجل المشاهدة
- **أدراج ونوافذ** — قفل تمرير الجسم، Escape للإغلاق، درج فلاتر بحركة `slideInStart` وزر «عرض النتائج»
- **شريط/تذييل** — قائمة جوال محدودة الارتفاع، رابط واتساب في التذييل، تخطيط مرن `flex` للصفحة

### التحقق يدويًا

1. `npm run build` يجب أن ينجح
2. افتحي `/` على عروض تقريبية: جوال ~390، جهاز لوحي ~768، سطح مكتب 1440/1920 — تأكدي من عدم وجود تمرير أفقي وكسر عربي
3. افتحي مسارًا غير موجود مثل `/does-not-exist` لصفحة 404
4. فرّغي السلة / احذفي عنوانًا / امسحي «شاهدتِ مؤخرًا» — يجب ظهور حوار تأكيد
5. راجعي منتجًا نافدًا وآخر بكمية منخفضة على البطاقات وصفحة المنتج
6. اختبري فلاتر الجوال ودرج السلة وبحث ⌘K



## المرحلة A+B+C — لوحة الإدارة

واجهة إدارة عربية RTL منفصلة عن المتجر (mock فقط — Zustand + localStorage):

| المسار | الوصف |
|--------|--------|
| `/admin/login` | دخول إداري وهمي |
| `/admin` | لوحة KPIs غنية + مخططات بسيطة + تنبيهات مخزون + بانتظار الدفع + روابط سريعة |
| `/admin/orders` · `/admin/orders/[id]` | فلاتر، تحديد جماعي + ملاحظات، تصدير CSV، تلميح واتساب للتحويل البنكي |
| `/admin/products` · `/admin/products/new` · `/admin/products/[id]` | جدول مع ترقيم صفحات، تفعيل/تعطيل جماعي، منتج جديد، روابط صور، شارات مخزون |
| `/admin/categories` | تعديل الأقسام (اسم، وصف، slug، صورة، نشط) |
| `/admin/offers` | CRUD حملات العروض |
| `/admin/customers` · `/admin/customers/[id]` | العملاء المستخرجون من الطلبات |
| `/admin/users` · `/admin/users/new` · `/admin/users/[id]` | مستخدمون + منع حذف/تعطيل آخر `super_admin` |
| `/admin/roles` · `/admin/roles/[id]` | أدوار + عدد المستخدمين لكل دور + تسميات صلاحيات عربية |
| `/admin/activity` | سجل تدقيق وهمي |
| `/admin/settings` | اسم المتجر، واتساب، حسابات بنكية (+ إضافة/حذف) |

**حسابات تجريبية** (كلمة المرور `demo123` — أي بريد/كلمة مرور أخرى تدخل كمدير أيضًا):

- `super@naqshat.ye` — مدير أعلى (كل الصلاحيات)
- `admin@naqshat.ye` — مدير (بدون إدارة الأدوار)
- `ops@naqshat.ye` — تشغيل (طلبات/منتجات/أقسام/عروض/عملاء)
- `viewer@naqshat.ye` — مشاهدة فقط
- `disabled@naqshat.ye` — معطّل (يُرفض الدخول)

**تخزين:** `naqshat-admin-auth` · `naqshat-admin-data` · `naqshat-admin-ops` · `naqshat-orders`

**UX عام:** شريط علوي مع جرس إشعارات وانتقال سريع ⌘K، قائمة جوال درج، مسار تنقل (breadcrumbs)، هياكل تحميل، صلاحيات تُفرض على الروابط والإجراءات.

> دمج المنتجات المخصّصة/التجاوزات **إداري فقط** — واجهة المتجر تبقى على بيانات البذرة الثابتة ولن تنكسر.

### التحقق يدويًا (Admin polish)

1. افتحي `/admin` → تحويل إلى `/admin/login` إن لم تكوني مسجّلة
2. ادخلي `super@naqshat.ye` / `demo123` — راجعي KPIs والمخططات وتنبيهات المخزون وبانتظار الدفع
3. جربي جرس الإشعارات و⌘K للانتقال السريع
4. `/admin/products/new` — أنشئي منتجًا بروابط صور؛ راجعي الترقيم والتفعيل الجماعي في القائمة
5. `/admin/orders` — صدّري CSV، حدّدي طلبات وطبّقي حالة + ملاحظة؛ افتحي طلبًا بانتظار الدفع وراجعي تلميح واتساب
6. `/admin/users` — حاولي تعطيل/حذف آخر مدير أعلى (يجب الرفض)؛ راجعي `/admin/roles` وعداد الاستخدام
7. `/admin/activity` — سجل الأحداث الوهمي
8. `/admin/settings` — أضيفي حسابًا بنكيًا واحفظي مع التحقق من الحقول
9. ادخلي كـ `viewer@naqshat.ye` — تعديل معطّل وروابط المستخدمين/الأدوار مخفية
10. افتحي المتجر `/` — يجب أن يعمل كالمعتاد
11. `npm run build` يجب أن ينجح
